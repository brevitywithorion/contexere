- **`contexere doctor --mcp` asks each configured MCP server whether it answers (#1095)**: `doctor` checked Contexere's own hook and MCP entry and nothing else, so a setup carried to a new machine could list servers that do not start. With the flag, each server from the same list as `contexere carry list` (#1092) is started over stdio or connected to over HTTP and sent `initialize`, `notifications/initialized`, and `tools/list`. One line per server: reachable with the tool count, failed with the reason, or skipped when a key it reads from the environment is not set. The wait is 5 seconds per server and the process is killed at the deadline, so one hung server cannot hold the command; the servers are asked together, so the wait does not stack. The default `doctor` does not start anything, and `contexere --mcp` (the server hosts already launch) is unchanged. Nothing is written, and env values, header values, and command arguments are not printed. A fixture with one server that answers, one that exits, and one that sleeps reports three different lines and returns at the deadline rather than waiting out the sleep.
